# Build complete before launch, no public beta

The server goes live only when the full feature set is finished. There is no public test phase, no soft launch, and no partial release. We accept a long pre-launch period with nothing playable, because no public feedback loop exists until then — bugs, balance problems and "is this actually fun" are all unvalidated until launch day.

## Consequences

- No player-driven bug reports during development. Everything found before launch is found by us, on our own machine, which is a far slower and less representative loop.
- Solo burnout is the primary project risk. There is no external accountability between "started" and "launched", and no server running to keep the work feeling productive.
- The feature list becomes the schedule. Any addition to it is a direct delay to launch, so the list must be closed and finite — an open-ended "everything" cannot be built to completion, so it has to become a named, finite set before work starts.
- Because we committed to a hand-rolled core (ADR-0002) there is nothing to release in the interim, so this decision is what makes the pre-launch period long rather than merely untidy.
- The three-month artifact rule (unjoinable from the server browser) does not bite pre-launch, but the release cadence obligation starts at launch.
